# Review batch — 2026-09-25

Nine read-only reviewers: five for correctness (chunk system; GPU offload; SuperChunk's worldgen
mixins; integration/config/compat; the bundled C2ME, VMP, Lithium and Starlight layers) and four
for performance (worldgen CPU hot paths; end-to-end chunk flow; the GPU pipeline; runtime, IO and
memory). Every finding below was checked against the code before being fixed; items not fixed are
listed at the end with the reviewer's estimate. Tests: see "Verification".

## Fixed — correctness

Data loss and hangs
- **Loaded chunks were never saved until they unloaded.** The C2ME port kept upstream's Yarn name
  `isAccessible()` for `ChunkHolder.wasAccessibleSinceLastSave()`, so it overrode nothing and
  vanilla's flag stayed false: autosave, the singleplayer pause save and `/save-all` skipped every
  chunk. A crash or kill lost every change since the chunks loaded. Now overrides
  `wasAccessibleSinceLastSave()` / `refreshAccessibility()` as upstream does
  (`NewChunkHolderVanillaInterface`).
- **`/save-all flush`, backup-mod flushes and server stop could spin forever.** The kept
  `MixinEntityChunkDataAccess` moves entity deserialization onto the main-thread queue, but
  upstream's shutdown fix that pumps that queue during `saveAll` had not been ported. Ported as
  `opts/scheduling/mixin/shutdown/MixinServerLevel` + `MixinPersistentEntitySectionManager`.
- **Resource reloads could hang.** `Util.sequence` and `Util.sequenceFailFast` had swapped bodies
  (Yarn `combineSafe`/`combine` mapped the wrong way round), so a reload listener that failed in
  its prepare stage left `SimpleReloadInstance` waiting forever (`opts/allocs/MixinUtil`).
- **Freeze next to a chunk that failed to generate** (`jjthunder-freeze-2026-09-25.md`), plus two
  follow-ups: the no-tick and predictive loaders no longer keep load slots for chunks stuck behind
  a broken one (`StuckLoadSweeper`: a few broken chunks in view stopped view-distance loading), and
  a broken chunk is no longer revived by a late-cancelled unload (`ReadFromDiskAsync`: the revived
  holder hit "Duplicate setDependencies call" and wedged, invisible to the freeze fix).
- `c2me.ioSystem.gcFreeChunkSerializer` is now always off: that saver never writes NeoForge's chunk
  data attachments and skips `ChunkDataEvent.Save`, so it lost other mods' data on every save.

Compatibility
- **ScalableLux, C2ME and Noisium are declared incompatible.** Each crashed the launch with a raw
  Mixin error when installed next to SuperChunk (reproduced; `compatibility.txt`). Radium also gets
  the same load-order pin as Lithium.
- **Stand-down upgrades (`MixinTargetScan`).** Read-only accessors no longer count as foreign
  (Create's Ponder and ModernFix had switched the biome cell path off in most real packs); the
  scan now answers per method (overwrites, injector calls, MixinExtras wraps); and it probes 18
  more classes. Uses:
  - the five whole-method replicas (ore placement, placed features incl. the inlined modifiers,
    heightmap priming, palette `getAll`, Xoroshiro reseed) run the original when another mod hooks
    them (`ForeignHooks`; owo-lib's ore hook was being skipped);
  - the flat climate search also checks `Climate.TargetPoint`/`Parameter`, the ore-RNG reuse checks
    `OreVeinifier`, and a biome-cache hook uses `require = 0` so a foreign `getBiome` overwrite
    cannot crash the boot.
- **GPU mode respected other mods' worldgen hooks only in part.** Compact block ids stand in for
  the whole per-block fill, so YUNG's API (Better Strongholds' bury adaptation, its aquifer
  override) was skipped. Ids are now off while another mod hooks that path (one WARN names it),
  and a modded beardifier type fails closed.
- GPU block ids are tagged with the dimension route they were decided for; a same-shaped other
  dimension can no longer take them. Fluid post-processing marks are written in vanilla's order.
  A fault inside a fault no longer runs the original loop over a half-restored chunk.
- Optional-target mixins (Sodium 0.6 vs 0.8, Skein's two package names, DH's two step classes) are
  skipped when their class is absent, instead of logging WARNs every boot.
- The GC advisory no longer edits `user_jvm_args.txt` unless asked (`-Dsuperchunk.gc.autoConfig=true`):
  switching a memory-capped host to ZGC can cause OOM kills. `c2me.*` values are trimmed. The End
  biome cache stands down for Simply Improved Terrain (upstream patch 0009). Stale docs fixed.

Logging (requested): `logging.verbose` (default false) — SuperChunk writes only warnings and errors;
per-second metrics are off and cost nothing unless verbose. 73 → 8 lines on a test boot.

## Fixed — performance
- GPU batch completer: polls and parks instead of NVIDIA's spinning `clWaitForEvents` (it burned
  0.7–0.9 of a core). `-Dsuperchunk.gpu.completerPollMicros=0` restores the blocking wait.
- The GPU decide program's source is now deterministic, so it is reused from the disk cache instead
  of being rebuilt (and re-cached) on every boot.
- `tickChunks` lists a non-ticking FULL chunk only when it has changes to broadcast (was every FULL
  chunk: ~1.7 ms/tick at view distance 44).
- Storage threads spin at most 2 ms after a burst (was ~0.3 s of 10 µs parks per thread).
